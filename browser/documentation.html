SingulaX Browser Reference

Documentation.

A searchable guide to the browser runtime, IDE-facing APIs, input, drawing, data, project execution, and the built-in 3D engine. This page documents the browser-side implementation, centered on runtime.js.

Architecture

HOW IT FITS TOGETHER

Browser execution pipeline

SingulaX source
   ↓
browser IDE / app.js
   ↓
SingulaxRuntime in runtime.js
   ↓
lexer/parser/executor + built-in APIs
   ↓
frame / host callbacks
   ↓
browser renderer, input, audio and UI

The browser IDE does not depend on sglx.py to execute a project. The browser runtime is JavaScript. runtime.js parses SingulaX, executes it, owns the environment of built-in functions, and sends drawing/scene frames to the browser host.

Language & Runtime

CORE

Comments

Browser parsing removes //, #, and -- comments where supported by the parser. Strings are protected while stripping // comments.

Variables and expressions

local speed = 5
var score = 0
score += 10
name = "SingulaX"
alive = true

The runtime evaluates expressions against the current scope and exposes built-ins through its environment. It supports arithmetic, comparisons, boolean operators, function calls, object properties, lists, and JavaScript-backed values.

Control Flow

LOGIC

Conditionals

if score > 10 then
    say("High score")
elseif score == 10 then
    say("Exactly 10")
else
    say("Low score")
end

Loops

while alive do
    update()
end

repeat 10 times
    say("tick")
end

for i = 1, 10 do
    say(i)
end

each item in items do
    say(item)
end

forever
    game_loop()
end

break exits a loop and continue skips to its next iteration. The runtime also includes safety limits on long-running loops.

Wait/repeat-until logic

wait(1)
wait.until(condition, "done")
repeat.until(task, "done")
repeat.until.statement(statement, "done")

These facilities are implemented by the runtime and yield periodically so browser execution can continue.

Functions & Data

TOOLS

Functions

function add(a, b)
    return a + b
end

score = add(10, 5)

Functions create child scopes. Arguments are placed in that child scope, and return sends a value back.

Lists

APIPurpose
list(...items)Create a list.
push(list,value)Add an item.
pop(list)Remove and return the last item.
list_get(list,index)Read an item.
list_set(list,index,value)Write an item.
list_remove(list,index)Remove an item.

Data, JSON and randomness

data() creates a simple object; data.store/find/has/clear provides a runtime data store. to_json() and from_json() handle JSON. random(), random_int(), and random_choice() provide randomness.

Math

Built-ins include abs, floor, ceil, round, sqrt, pow, sin, cos, tan, asin, acos, atan, atan2, min, max, clamp, lerp, pi, e, tau, deg, and rad.

Input

KEYBOARD · MOUSE · TOUCH · GAMEPAD

Keyboard

APIMeaning
key_down(key)True while a key is held.
key_pressed(key)True for a press event. The event is consumed when read.
if key_down("w") then
    move3d("player", 0, 0, -speed)
end

Mouse

mouse_down(button), mouse_clicked(button), mouse_x(), mouse_y(), mouse_dx(), mouse_dy(), mouse_lock(), mouse_unlock(), and mouse_locked() expose mouse state and pointer-lock controls.

Touch

touching(), touch_x(), touch_y(), touch_started(), and touch_ended() expose the runtime's primary touch state. Mobile UI controls can be managed through the controls API.

Gamepad

gamepad_connected(index), gamepad_button(index,button), and gamepad_axis(index,axis) read connected controller state.

Touch/control interface

controls.all(), controls.reset(), controls.only(...names), controls.show(...names), and controls.hide(...names) call the browser host's mobile control layer. The same operations also exist as controls_all, controls_reset, controls_only, controls_show, and controls_hide.

Timing & Audio

RUNTIME SERVICES

wait(seconds) pauses asynchronously, wait_ms(milliseconds) uses milliseconds, and time()/seconds() return the current performance time in seconds. play_audio(asset,loop) and stop_audio(asset) delegate audio playback to the browser host.

Projects & Assets

PROJECT EXECUTION

Running source

runtime.run(source) parses and executes one source string. runtime.runProject(project,{entry}) loads the project's source files, joins selected .sglx files, supplies project assets, and runs the resulting source.

Files and assets

The runtime exposes file_read(path), file_write(path,content), asset(path), and asset_url(path). These delegate storage/file behavior to the host instead of assuming browser filesystem access.

3D Engine

BUILT-IN

3D pipeline

scene3d()
   ↓
object3d() / camera3d() / light3d()
   ↓
position3d() / rotation3d() / scale3d()
   ↓
materials + meshes + colliders
   ↓
render3d()
   ↓
3D scene frame
   ↓
browser WebGL renderer

The runtime is game-agnostic. It manages the scene and serializes it into a 3dscene frame for the browser host's renderer.

3D Math

UNDER THE HOOD

Vectors

The internal engine represents 3D vectors as {x,y,z}. Its core operations are vector creation, addition, subtraction, scalar multiplication, length, and normalization.

vadd(a,b)   → a + b
vsub(a,b)   → a - b
vmul(a,n)   → a × n
vlen(a)     → √(x²+y²+z²)
vnorm(a)    → unit direction

Rotation math

The internal rotXYZ routine applies X, Y and Z rotations using sine and cosine. Object parenting uses this transformation when calculating world positions. SingulaX's rad() and deg() helpers convert between degrees and radians.

Object capabilities under the hood

Objects have position, rotation, scale, visibility, size, material, collider, mesh, parent and children. The internal object API also supports set_position, set_rotation, set_scale, move, rotate, look_at, mesh_set, material_set, collider_set, add_child, and remove_child.

Camera & Lighting

VIEW

Camera

camera3d(name) creates a camera. camera3d_position(), camera3d_rotation(), and camera3d_fov() control it. Internally cameras default to a 75° FOV, a near clip of 0.05, a far clip of 1000, and sensitivity 1. The internal camera also supports clip and sensitivity settings.

Lights

light3d(name), light3d_position(), light3d_rotation(), light3d_intensity(), and light3d_color() configure lights. Internal lights have a type, intensity, range and color.

Scene environment

scene3d_ambient(value) controls ambient light. scene3d_background(value) sets the background. scene3d_fog(enabled,density,color) configures fog.

Materials & Meshes

SURFACES + GEOMETRY

Materials

material3d(name) retrieves or creates a material. material3d_set(object,color,metallic,roughness,opacity) applies material values directly to an object. The runtime stores color, metallic, roughness, opacity and emission.

Custom meshes

mesh3d("triangle")
mesh3d_vertex("triangle", 0, 1, 0)
mesh3d_vertex("triangle", -1, -1, 0)
mesh3d_vertex("triangle", 1, -1, 0)
mesh3d_face("triangle", 0, 1, 2)

object3d("shape", "custom")
mesh3d_use("shape", "triangle")
render3d()

A mesh is a list of vertices and faces. Faces contain vertex indices. This lets SingulaX describe custom geometry rather than only using primitive object types.

Collision & Raycast

INTERACTION

Colliders

collider3d(name,type,size) attaches collider information to an object. The current runtime is intentionally simple and does not implement a full rigid-body physics engine.

Raycasting

hit = raycast3d(origin, direction, 1000)

The runtime normalizes the direction and tests visible collidable objects. It chooses the closest intersection and returns name, distance, and point, or null if nothing is hit. This is useful for FPS shooting, interaction, picking, and line-of-sight logic.

The current raycast uses a simplified sphere-style intersection derived from collider size and object scale. It is not a full mesh collision test.

Browser IDE Logic

HOST BRIDGE

Host callbacks

The runtime accepts a host object. It can receive output, frames, errors, input, file operations, audio, mouse-lock state, control visibility, and 3D mode changes. This keeps the language runtime separate from browser UI details.

Input injection

The host calls runtime.setInput() with keys, releases, pressed keys, mouse state, mouse deltas, buttons, clicks, touch state, touch events, and gamepads. The runtime then exposes those values through the SingulaX input APIs.

Frames

2D commands are stored in runtime.frame. A 3D render creates a frame containing {type:"3dscene",scene:...}. emitFrame() sends a copy to the host. This is the bridge between language execution and the IDE preview.

Quick Examples

START HERE

Simple 3D scene

scene3d("main")
scene3d_background("#050816")
scene3d_ambient(0.2)

object3d("cube", "cube")
position3d("cube", 0, 0, 0)
scale3d("cube", 2, 2, 2)
material3d_set("cube", "#4be0e3", 0.3, 0.3, 1)

camera3d("main")
camera3d_position("main", 0, 3, 8)
camera3d_fov("main", 75)

light3d("sun")
light3d_position("sun", 5, 10, 5)
light3d_intensity("sun", 2)

render3d()

Basic FPS-style movement logic

speed = 0.1

forever
    if key_down("w") then
        move3d("player", 0, 0, -speed)
    end

    if key_down("s") then
        move3d("player", 0, 0, speed)
    end

    if key_down("a") then
        move3d("player", -speed, 0, 0)
    end

    if key_down("d") then
        move3d("player", speed, 0, 0)
    end

    render3d()
    wait(0.016)
end

This is intentionally simple. A full FPS controller can add camera-relative movement, mouse look, jumping, sliding, collision, raycast shooting, and mobile controls.
